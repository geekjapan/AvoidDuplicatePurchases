# 表記揺れ正規化の検証(Issue #7)— 確定版

調査日: 2026-08-03。**実購入データ 2417 listing による実測**(DLsite 575 / FANZA 同人 1742 / ブックス 6 / 動画 93 / PCゲーム 1)。

**本リポジトリは public のため、実タイトルを含むサンプルと計測レポートは `samples/`(`.gitignore` 済み)にのみ置く。**
この README には作品を特定しない範囲の例だけを載せる。再現するには「採取」の手順を実行すること。

## 結論(先に)

1. **完全一致で拾えるサイト横断ペアは 16 組。** 効いたルールは 3 つだけ(NFKC・店舗版マーカー除去・記号除去)。カナ寄せと巻数正規化はこのデータでは寄与ゼロ。
2. **ブラケットの一律除去は破綻する。** 入れると 16 → 205 組に膨らみ、増分はほぼ全部が偽陽性。
3. **dice 類似度の閾値だけでは真偽を分離できない。** 偽陽性が 0.833、真陽性が 0.877〜0.973 に出て帯が重なる。
4. → **2段構え**: 完全一致だけ自動マージ、類似帯は人がレビューする候補キュー(#1 のカート「自動削除はしない」と同じ判断)。
5. **メーカー名は強力なゲート**。dice 0.6 以上の候補 197 組は 100% メーカー名も一致した。

## 採用したルール(層順)

`key(title, level)` は L1 → L2 → L5 → L3 → L4 の順に適用する(巻数落としは記号除去より前。`(3)` を先に消さないと数字が本文に混ざる)。

| 層 | 内容 | 新規に拾ったペア |
|---|---|---|
| L1 | NFKC + 小文字化 + 空白潰し | +4 |
| L2 | **店舗固有の版マーカーだけ**除去(`【FANZA限定版】` `【DL版】` 等) | +10 |
| L3 | 記号・空白を全除去(文字と数字だけ残す) | +2 |
| L4 | カタカナ→ひらがな、長音・小書き・濁点揺れの吸収 | +0 |
| L5 | 巻数・話数表記の除去(`第3巻` `vol.12` `(1)`) | +0 |

L1 が拾ったのは `!` と `！` の差だけ。L2 は `【FANZA限定版】` の有無だけの差。L3 は `✨…✨` と `【…】` という装飾文字の違い。
L4/L5 の寄与がゼロなのは**このユーザーの購入内容(同人音声が大半)**の性質で、ブックス比率が上がれば L5 が効くはず。**残す**判断にした。

### 却下: ブラケットの一律除去

同人音声は**識別情報そのものが `【】` の中にある**(演者名・使用玩具)。除去するとシリーズ全体が 1 つの鍵に潰れ、DLsite 側 n 件 × FANZA 側 m 件の総当たりで一致する。

```
【…実演】シリーズ名【演者A - 玩具X編】     ← 別作品
【…実演】シリーズ名【演者B - 玩具Y編】     ← 別作品
→ 一律除去すると両方「…実演シリーズ名」になって同一視される
```

`normalize.mjs` の `stripAllBrackets` として残し、**セルフチェックでこの失敗を固定**してある(再導入を試みたら壊れる)。

### 意図的に除去しないもの

- **`(無料版)` `【無料お試し版】`** — 体験版は**別商品**。除去すると本編と同一視され、買っていない物を「購入済み」と誤報する。実データにこのペアが存在した(dice 0.923)。
- **`【KU100】` `【バイノーラル】` `【オホ声】`** — 頻出(KU100 は 184 回・38 メーカー)だが、収録方式の違う別版が存在しうる。除去対象にしない。
- なお「多くのメーカーに跨るタグ=装飾」という自動判定は**成立しない**。`【FANZA限定版】` はこの corpus では 1 メーカーにしか出ない。denylist は明示列挙するしかない。

## 完全一致で拾えなかった真の重複(= 偽陰性の実態)

近傍帯(dice ≥ 0.75)66 組の中身。**機械的に吸収できない体系的な差**が 3 種類あった:

1. **FANZA 側だけ伏せ字** — `メスガキ`/`メス〇キ`、`犯され`/`犯●れ`、`強制`/`強○`(dice 0.88〜0.97)。伏せられた文字は復元できない。
2. **DLsite だけシリーズ番号を持つ** — `【○○No.9】` vs `【○○】`(0.88〜0.94)。番号を落とすとシリーズ内の別作品と衝突するので落とせない。
3. **FANZA 側で語を言い換え** — `JK…` → `現役…`(0.92)。

同じ帯に**偽陽性**も混在する:

- 演者違い(シリーズ内の別作品)が dice 0.833
- 体験版と本編が dice 0.923

→ **真陽性 0.877〜0.973 と偽陽性 0.833・0.923 が重なる。単一の閾値では切れない。**

## 候補キューのサイズ(閾値の判断材料)

| dice 閾値 | 候補総数 | うちメーカー名も一致 |
|---|---|---|
| 0.5 | 344 | 239 |
| 0.6 | 197 | 197 |
| 0.7 | **118** | 118 |
| 0.75 | 66 | 66 |
| 0.85 | 17 | 17 |

**0.6 以上では候補の 100% がメーカー一致。** メーカーをゲートにしても取りこぼしはなく、0.5 まで下げたとき初めて絞り込みとして効く。

## 設計への落とし込み(#7 の答え)

- **完全一致した正規化キーだけ自動マージする。**
- **dice ≥ 0.7 かつ正規化メーカー名一致**を候補キューとして管理画面に出し、**人が○×を付けたものだけ確定**する。確定は #6 の `listing.work_id_locked` に落ちる。
- **自動マージの閾値を上げて済ませない。** 誤報(買っていない物を購入済みと出す)は取り返しがつかないが、取りこぼしは候補キューで拾える。

### #6 のデータモデルとの噛み合わせ

- `match_key` の `kind` は当面 **`title`(L1〜L5 の鍵)と `maker`(L1〜L4 の鍵)の 2 種類**。
- 拡張の「別サイトで購入済み」判定は `match_key(kind='title')` の完全一致で引く。
- 候補キューの生成は `kind='maker'` で絞ってから dice を掛ける**バッチ処理**(全件総当たりは 2417² で回るが、増えるとつらい)。リアルタイム経路ではない。

## 成果物

- `normalize.mjs` — 正規化ルール + dice + 計測。`node normalize.mjs --selftest` でルール単体のセルフチェック(**却下ルールの失敗も固定**)、引数なしで `samples/` を読んで計測レポートを出す。
- `fetch-dlsite-meta.mjs` — `samples/dlsite-sales.json` の workno から公開 `product.json` を取得。**ブラウザ不要**(未ログインで 200)。
- `collect.js` / `collect-origin.sh` / `sink.mjs` — ログイン必須のライブラリ API をブラウザから採取して localhost へ POST する仕組み(下記)。

## 採取の手順と、途中で分かったこと

```
node sink.mjs &                                  # 127.0.0.1:8787 で待ち受け
sh collect-origin.sh https://play.dlsite.com/    # DLsite 購入 workno 一覧
node fetch-dlsite-meta.mjs                       # DLsite メタ(ブラウザ不要)
sh collect-origin.sh https://www.dmm.co.jp/dc/-/mylibrary/
sh collect-origin.sh https://book.dmm.co.jp/library/
sh collect-origin.sh https://video.dmm.co.jp/
sh collect-origin.sh https://dlsoft.dmm.co.jp/mypage/library/
node normalize.mjs > samples/report.txt
```

- **`window.__r` を osascript で分割読み出しする方式(#4/#5 の手順)は 2400 件規模で破綻した。** osascript が理由不明で単発失敗し、40KB チャンクを取りこぼして JSON が静かに壊れる。**ページから localhost へ POST させる**方式に変えると、ブラウザ操作は「1 オリジンにつき osascript 1 回」で済み、巨大文字列の読み出しが消える。
- **Chrome の Private Network Access**: 公開オリジン → `127.0.0.1` の POST には preflight が飛ぶ。`OPTIONS` に `Access-Control-Allow-Private-Network: true` を返さないと**リクエストが永久に pending のまま**(エラーにもならない)。`sink.mjs` で対応済み。
- **「Apple Events からの JavaScript を許可」は実行中に落ちることがある。** メニューの `✓` は当てにならず、実際に効くかは `execute javascript "1+1"` を叩いて判定するしかない。ON/OFF のトグルは自動化できずユーザーの手作業。
- DLsite の `product.json` は 591 件中 **16 件が取得できない**(販売終了等)。メタが無い listing は正規化の入力を購入履歴側の情報だけで組む必要がある。
